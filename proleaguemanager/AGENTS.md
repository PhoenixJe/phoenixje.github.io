# Proleague Manager Web Guide — Working Rules

이 문서는 `proleaguemanager` 웹 설명서를 수정할 때 반복해서 적용하는 기본 작업 원칙이다.

## 1. 작업 시작 전 확인

- 수정 전에 항상 현재 `index.html`과 `style.css`를 먼저 읽고 실제 구현 상태를 확인한다.
- 과거 대화나 추측보다 현재 저장소의 파일 상태를 우선한다.
- `images` 폴더의 실제 파일명도 확인한 뒤 참조한다.

## 2. 기존 완성 항목을 기준으로 작업

- `03 기능별 안내`의 이미 완성된 항목을 후속 기능 설명의 기본 템플릿으로 삼는다.
- 현재 기준 항목은 `01 참가자`, `02 팀선정`이다.
- 후속 항목은 기존의 HTML 구조, 접기 방식, 제목 체계, 본문 배치, 이미지·영상 배치, 간격, 클래스 사용 방식을 최대한 그대로 이어간다.
- 기존 완성 항목과 시각적으로 다른 새 디자인을 임의로 만들지 않는다.

## 3. HTML/CSS 수정 원칙

- 기존 HTML 구조와 CSS 클래스를 우선 재사용한다.
- 기존 스타일로 구현 가능한 경우 새 CSS를 추가하지 않는다.
- 새 CSS가 정말 필요한 경우에만 최소 범위로 추가한다.
- 기존 섹션의 스타일, 레이아웃, 간격을 작업 편의상 재정리하거나 리팩터링하지 않는다.
- 불필요한 클래스명 변경, 구조 변경, 정리 작업을 하지 않는다.
- 작은 변경 우선 원칙을 지킨다.

## 4. 설명서 구조 유지

- 설명서는 one-page 구조를 유지한다.
- 큰 섹션 구조는 기존 구성을 따른다.
- `03 기능별 안내`의 상세 기능은 기존 `<details>/<summary>` 접기 구조를 유지한다.
- 상세 항목 제목의 번호와 제목 스타일은 기존 구현을 그대로 따른다.
- 스크린샷 가이드 번호, 본문 소제목 등 기존 시각 규칙을 임의로 변경하지 않는다.

## 5. 문구 처리

- 사용자가 확정한 설명 문구는 의미나 문체를 임의로 다듬거나 재작성하지 않는다.
- 오탈자나 명백한 HTML 표기 문제 외에는 확정 문구를 그대로 반영한다.
- 기존 완료 섹션의 문구를 작업 범위 밖에서 임의로 수정하지 않는다.

## 6. 이미지/영상 처리

- `images` 폴더의 실제 파일명을 정확히 사용한다.
- 파일명 대소문자를 정확히 맞춘다.
- 이미지·영상 원본 파일 자체를 임의로 편집하거나 리사이즈하지 않는다.
- 웹페이지에서의 표시 크기는 기존 설명서의 CSS와 레이아웃 규칙을 따른다.
- 원본 픽셀 크기와 웹페이지 표시 크기의 1:1 일치를 강제하지 않는다.
- 기존 이미지·영상 표시 방식과 반응형 크기 정책을 우선 재사용한다.
- 자료를 임의로 다른 파일로 교체하지 않는다.
- 기존 설명서와 같은 방식으로 필요한 영역만 배치한다.

## 7. 작업 범위 준수

- 요청받은 항목만 수정한다.
- 다른 섹션의 문구, 스타일, 구조는 요청이 없는 한 건드리지 않는다.
- 사용자가 별도로 요청하지 않은 기능 개선이나 디자인 개선을 추가하지 않는다.
- 외부 패키지나 라이브러리를 추가하지 않는다.

## 8. 검증 및 보고

- 수정 후 HTML 구조와 참조 경로가 깨지지 않았는지 확인한다.
- 이미지·영상 경로의 파일명이 실제 파일과 정확히 일치하는지 확인한다.
- 기존 `01 참가자`, `02 팀선정`과 후속 항목의 시각 구조가 일관되는지 코드 기준으로 확인한다.
- 실제 브라우저의 최종 시각 판정은 사용자가 수행하므로, 코드만 보고 임의로 시각적 PASS를 선언하지 않는다.
- 작업 완료 후 수정한 파일과 변경 내용을 짧게 보고한다.
